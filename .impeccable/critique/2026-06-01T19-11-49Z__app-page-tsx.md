## Overall Impression

ฐานระบบแข็งแรงและเหมาะกับการใช้งานจริงขึ้นมากหลังเพิ่ม search, grouping และ alphabetical index โอกาสใหญ่ที่สุดคือทำให้ `เลือกรายชื่อ` เป็นพระเอกของหน้า โดยลดพื้นที่และสิ่งรบกวนที่อยู่ก่อน list บนมือถือ

## What's Working

1. Search, `ตามคิว / ก-ฮ`, grouped list และ index ด้านข้างแก้ปัญหารายชื่อจำนวนมากตรงจุด
2. สถานะสำคัญมีข้อความประกอบ ไม่พึ่งสีอย่างเดียว เช่น จำนวน `0/4`, สถานะซิงก์ และ lock note
3. Design token และ dark mode ค่อนข้างสม่ำเสมอ ใช้ primary, warning, danger และ disabled state เป็นระบบเดียวกัน

## Priority Issues

### [P1] Flow หลักถูกดันลงด้วย control หลายชั้น

**Why it matters:** ผู้ใช้ข้างสนามต้องหารายชื่อเร็ว แต่ต้องผ่าน header, control band, tabs, toolbar, sticky picker header และ voice picker ก่อนถึง list

**Fix:** บนมือถือยุบ header และ control band ให้กะทัดรัดขึ้น, ให้ search กับ toggle อยู่ติด list, และลด prominence ของ voice picker เมื่อไม่ได้ใช้งาน

**Suggested command:** `$impeccable distill หน้า กำลังตี บนมือถือ`

### [P1] Sticky header และ alphabetical jump ยังเปราะเมื่อความสูง header เปลี่ยน

**Why it matters:** เมื่อเลือกคน chip จะเพิ่มความสูงของ sticky area หัวหมวดอาจถูกบังหรือ jump แล้วหยุดผิดตำแหน่ง

**Fix:** วัดความสูง sticky header แบบ dynamic ผ่าน CSS custom property หรือ ref และใช้ค่านั้นกับ `scroll-margin-top`; อย่าใช้ offset คงที่

**Suggested command:** `$impeccable adapt alphabetical picker sticky behavior`

### [P2] Contrast ของ selected chip สีส้มไม่พอสำหรับข้อความสีขาว

**Why it matters:** `--selected-chip-bg: #ff894a` กับข้อความขาวอ่านยาก โดยเฉพาะกลางแจ้งหรือบนมือถือจอสว่าง

**Fix:** ใช้ข้อความสีเข้มบนสีส้ม หรือขยับพื้นหลังให้เข้มพอจนผ่าน contrast 4.5:1

**Suggested command:** `$impeccable audit color contrast`

### [P2] ภาษา UI ไทยและอังกฤษปนกันโดยไม่จำเป็น

**Why it matters:** `ลูก number`, `Room`, `Match` และ `admin` ทำให้ flow หน้างานสะดุดเล็กๆ และลดความเป็นกันเอง

**Fix:** เลือกคำไทยที่สั้นและตรง เช่น `ลูกที่`, `รอบ`, `จัดคู่ล่วงหน้า`; เก็บคำอังกฤษไว้เฉพาะคำที่กลุ่มใช้จริง

**Suggested command:** `$impeccable clarify หน้า กำลังตี`

### [P2] Alphabetical index ยังเสี่ยงเกินความสูง viewport

**Why it matters:** แม้ปุ่มเล็กลงแล้ว รายชื่อหมวดจำนวนมากยังทำให้ index ยาวเกินจอมือถือได้

**Fix:** จำกัดความสูง index, เพิ่ม internal scroll หรือแสดงเฉพาะหมวดที่มีข้อมูลพร้อม affordance ที่อ่านง่าย

**Suggested command:** `$impeccable adapt alphabetical index mobile`

## Persona Red Flags

### แอดมินประจำสนามที่ต้องกดเร็ว

- ต้องเลื่อนผ่านพื้นที่หลายส่วนก่อนถึงรายชื่อ
- เมื่อเลือกคนแล้ว chip เพิ่มความสูง ทำให้ตำแหน่งหมวดขยับ
- คำว่า `ลูก number` ใช้เวลาตีความเกินจำเป็น

### สมาชิกในกลุ่มที่ช่วยใช้งานเป็นครั้งคราว

- อาจไม่รู้ทันทีว่า `ตามคิว / ก-ฮ` เปลี่ยนวิธีหารายชื่ออย่างไร
- ไม่มีคำอธิบายสั้นๆ ว่า index ด้านข้างกดเพื่อ jump ได้
- ปุ่มและสถานะหลายชนิดอยู่ใกล้กัน ทำให้ลังเลว่าจะเริ่มตรงไหน

### ผู้ใช้มือถือกลางแจ้ง

- chip สีส้มข้อความขาวมี contrast ต่ำ
- index แนวตั้งอาจล้น viewport
- sticky area หลายชั้นลดพื้นที่ list ที่มองเห็นพร้อมกัน

## Minor Observations

- Footer version มีประโยชน์กับการ support แต่ไม่ควรแย่งพื้นที่ใน flow หลัก
- Dark mode มี token ครบพอสมควร ควรตรวจ contrast จริงทั้งสองโหมด
- Empty state มีข้อความแล้ว แต่สามารถบอก action ถัดไปให้ตรงขึ้น เช่น `เพิ่มชื่อผู้เล่นด้านบนเพื่อเริ่มเลือกคน`
